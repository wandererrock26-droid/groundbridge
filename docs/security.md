# Безопасность: пароль панели и модель привилегий

## Авторизация веб-панели

Вход по паролю включён **всегда** — выключить его через config.yaml нельзя.
Станция управляет реальной машиной и часто висит на собственной WiFi-точке,
поэтому «панель без пароля» не должна включаться одной строчкой в конфиге.

Пароль **из коробки — `roverlink`**. Это не секрет: он написан здесь, в
README и в выводе установщика — ровно затем, чтобы свежая установка
открывалась сразу, а не блокировала сама себя. Как защита он не работает.

**Смени его при первом входе:** панель → «Система» → «Пароль веб-панели».
Форма спрашивает текущий пароль, новый и подтверждение, минимум 6 символов.

Свойства:

- Один общий пароль (не многопользовательская система). Сессия — подписанный
  cookie; авторазлогин после `auth.session_timeout_minutes` (по умолчанию 30)
  без активности.
- Пароль хранится **только как хеш** (werkzeug, pbkdf2) в
  `data/panel_auth.json` (0600). Самого пароля на устройстве нет.
- `data/` не трогается при обновлении: распаковка нового архива проекта
  поверх старого свой пароль не сбрасывает.
- Смена пароля повышает счётчик поколения, и сессии на **других**
  устройствах становятся недействительными сразу, не дожидаясь таймаута.
- Подсказка со стандартным паролем на экране входа показывается, только
  пока пароль стандартный. Сменил — подсказка исчезла.
- Ключ подписи cookie генерируется автоматически и хранится в
  `data/flask_secret.key` (0600) — сессии переживают перезапуск сервиса.
- Известное ограничение: у пассивно открытой вкладки с истёкшей сессией уже
  установленный WebSocket продолжит получать статусы до первого действия —
  тогда произойдёт редирект на вход. Новые подключения блокируются сразу.

Задать пароль из терминала (например, если в панель уже не войти):

```bash
cd ~/roverlink
source venv/bin/activate
./scripts/set_panel_password.sh
deactivate
sudo systemctl restart roverlink
```

Забыл пароль — сброс на стандартный:

```bash
rm ~/roverlink/data/panel_auth.json
sudo systemctl restart roverlink
```

`auth.password_hash` в config.yaml остался только для совместимости со
старыми установками: панель читает его, если `data/panel_auth.json` ещё нет.

## Модель привилегий: узкие sudoers-хелперы

Сервис работает от обычного пользователя. Всё, что требует root, вынесено в
отдельные скрипты с точечными правилами NOPASSWD (ставит install.sh):

| Хелпер | Что может | Почему это безопасно |
|---|---|---|
| `zerotier-cli` (бинарник) | join/leave/статус ZeroTier | правило только на конкретный путь бинарника |
| `roverlink-fan-control.sh` | скорость вентилятора | сам находит устройство, принимает только число 0–4 — писать в произвольный файл нельзя |
| `roverlink-wifi-ap-update.sh` | SSID/пароль точки доступа | работает только с профилем `roverlink-ap`, имя профиля снаружи не принимается |
| `roverlink-declone.sh` | сброс ZeroTier ID, SSH-ключей, machine-id, hostname, reboot | вызывается кнопкой панели; смени стандартный пароль панели, прежде чем раздавать доступ |

Правила лежат в `/etc/sudoers.d/roverlink-*` и проверяются `visudo -c`
при установке.

## Чувствительные файлы

Все runtime-файлы — в `data/` (в .gitignore):

- `data/flask_secret.key` — ключ подписи сессий (0600);
- `data/panel_auth.json` — хеш пароля панели (0600);
- `data/zerotier_state.json` — может содержать Central API-токен (0600);
- `data/*_state.json` — сохранённые настройки панели.

`config.yaml` тоже в .gitignore — в репозитории только
`config.example.yaml` без секретов.

## Сетевая поверхность

Панель (8080), MAVLink (14550/udp) и MediaMTX (8554/8888/8889/8189) слушают
все интерфейсы и рассчитаны на **доверенные сети**: LAN, WiFi-точка Pi,
приватная сеть ZeroTier. Не пробрасывай эти порты напрямую в интернет:
MediaMTX настроен без авторизации путей, а видеопоток и MAVLink не
шифруются. Для удалённого доступа используй ZeroTier.
