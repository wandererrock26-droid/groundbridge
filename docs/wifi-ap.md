# WiFi-точка доступа: работа «в поле»

## Идея

Все сервисы слушают `0.0.0.0`, поэтому как только Pi поднимает собственную
WiFi-точку доступа — панель, MAVLink и видео доступны через неё точно так
же, как по LAN или ZeroTier. Ноутбук оператора подключается к WiFi машины
напрямую, без роутера и интернета.

## Панель работает полностью офлайн

У клиента, подключённого к точке доступа Pi, обычно нет интернета — поэтому
панель не тянет ничего с CDN: `socket.io.min.js`, стили и скрипты раздаются
с самой Pi. `socket.io.min.js` скачивается один раз при установке; если
интернета тогда не было, докачай вручную:

```bash
curl -fL https://cdnjs.cloudflare.com/ajax/libs/socket.io/4.7.5/socket.io.min.js \
  -o ~/roverlink/webapp/static/socket.io.min.js
```

Без этого файла страница откроется, но «живая» часть (каналы, статусы)
работать не будет — панель покажет «socket.io не загружен».

## Точка доступа поднимается сама при первой установке

`install.sh` настраивает AP **по умолчанию**, без дополнительных флагов:

- регуляторный регион WiFi (**RU** по умолчанию) и снятие программной
  блокировки rfkill применяются **всегда**, даже с `--no-wifi-ap` — без этого
  wlan0 может вообще не появиться в системе;
- создаётся профиль NetworkManager `roverlink-ap` с autoconnect — точка
  поднимается сама при каждой загрузке;
- стандартные реквизиты: SSID **roverlink**, пароль **roverlink**.

> ⚠ **Обязательно смени стандартный пароль** после первого входа: панель →
> «Система» → «WiFi точка доступа». Стандартный пароль знают все, кто читал
> этот файл.

Свои SSID/пароль сразу при установке (это же принудительно пересоздаёт
существующий профиль):

```bash
./install.sh --wifi-ssid "MyDrone" --wifi-password "пароль-от-8-символов"
# другой интерфейс:      --wifi-interface wlan1
# другой регион WiFi:    --wifi-country UA   (по умолчанию RU)
# не настраивать AP:     --no-wifi-ap
```

Повторный запуск установщика **без** флагов `--wifi-ssid/--wifi-password`
существующий профиль не трогает — пароль, изменённый из панели, не
сбрасывается.

**Нюанс:** если wlan0 уже использовался для подключения к домашнему WiFi —
он переключится в режим AP, и Pi перестанет ходить в интернет через WiFi
(останется Ethernet).

## Дальнейшая смена SSID/пароля — из панели

Вкладка «Система» → «WiFi точка доступа» → новые SSID/пароль → чекбокс
подтверждения → «Сохранить и применить». Работает через узкий root-хелпер,
который умеет менять **только** профиль `roverlink-ap` (см.
[security.md](security.md)). Применение занимает пару секунд, точка доступа
на это время обрывается.

## Использование

IP Pi для клиентов точки доступа обычно `10.42.0.1`:
панель `http://10.42.0.1:8080`, MAVLink — тот же IP, порт 14550, видео —
RTSP/WebRTC/HLS на нём же.

## Диагностика

```bash
nmcli connection show                # есть ли профиль roverlink-ap
nmcli connection show --active       # активен ли сейчас
nmcli device status
journalctl -u NetworkManager -f
```

Пересоздать с другими SSID/паролем — повторный запуск
`install.sh --wifi-ssid ... --wifi-password ...` (идемпотентно).
Удалить: `sudo nmcli connection delete roverlink-ap`.
