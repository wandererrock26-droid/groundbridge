# AYAKS Mesh — карта протокола (для вкладки панели)

Этот документ — не инструкция к модему, а разбор того, **как с модемом
говорит его штатный конфигуратор**, чтобы повторить чтение состояния прямо
во вкладке станции. Всё ниже получено из двух независимых источников и сведено
вместе; догадок в таблицах эндпоинтов нет — только то, что подтверждено.

Разбор законен и уместен: мы документируем протокол ради совместимости со
своим же железом. Инструкция производителя прямо называет это штатной
возможностью — «Web-based network management / **API for secondary
development** / SNMP».

## Сканер подсетей — кто ещё в сети и нет ли конфликта

Первый блок вкладки «Меш». Меш — общая среда: за каждым модемом свои
устройства, и все они оказываются в одной подсети. Модемов бывает 2–6, у
каждого машина, камера, ноутбук техника. Достаточно одного человека, поднявшего
себе адрес «как у всех», — и он совпадёт с адресом станции. Дальше связь с
машиной рвётся без видимой причины: снаружи это выглядит как «глючит меш», а
на деле два устройства делят один адрес.

Кнопка **«Сканировать сеть»** проходит все подсети, где стоит станция, и даёт:

- список занятых адресов с пояснением, **что это за устройство** — меш-модем
  (отвечает по порту 3450), станция RoverLink (представляется сама через
  `/api/identify` — имя и версия), RTSP-камера (554), устройство с веб-мордой
  (80), компьютер по SSH (22), плюс производитель по MAC;
- **конфликт адресов** отдельным красным блоком: если на нашем адресе отвечает
  чужой MAC, сканер прямо пишет, чей именно и чем это грозит;
- свой адрес помечен «это мы» — видно, где в списке станция.

Как ищем: параллельный ping по подсети (он же наполняет ARP-таблицу ядра),
затем `ip neigh` для MAC-адресов, затем короткие TCP-пробы по характерным
портам только у откликнувшихся. Если `ping` в системе нет (минимальный образ),
присутствие определяется по открытым портам — сканер не слепнет.

Сканирование запускается **только по кнопке**: меш узкий, и греть его фоновыми
проходами станция не должна. Подсети шире `/23` пропускаются с пометкой —
такая маска почти всегда ошибка настройки, а проход по ней занял бы часы.

## Что за железо

| | |
|---|---|
| Модель | **XK-F359 Mesh Radio** |
| Производитель | Shenzhen Xingkai Tech Co., Ltd. |
| Прошивка | `mesh` 2.12.2-rc8 (M0053), «Mesh Interface v1.9» |
| Имя сети (наша) | `NRTK` |
| Диапазон | L-band, `freqList` 1302–1498 МГц, 41 точка с шагом 5 МГц |
| Режим частот | `adaptiveHopping2`, `rangeMode 25`, `span 3` |
| Наши модемы | `192.168.1.171`, `192.168.1.241` (из сохранённых `.msconf`) |

Прошивка (`mesh.xupdate`) и веб-морда (`mesh_web_hxs…zip`) в поставке
**зашифрованы** (AES): образ прошивки — сплошной шум, zip веб-интерфейса — с
AES-записями без пароля у нас. Поэтому источником протокола служит **сам
конфигуратор** (`MeshConfig.exe`, .NET) — он не зашифрован, и по нему видно
каждый запрос, который он шлёт модему.

## Транспорт

Обычный **HTTP на порту 3450**, тело — JSON. Конфигуратор ходит через
`HttpClient` (`GetJsonFromUrlAsync` / `PostJsonToUrlAsync`), парсит ответ
Newtonsoft.Json. Базовый адрес собирается как `http://<ip>:3450`.

Значит, вкладке станции не нужен ни конфигуратор, ни его формат файлов — она
может ходить к модему теми же GET-запросами и показывать разобранный JSON.

## Эндпоинты чтения (это и есть Этап 1)

Все — `GET http://<ip>:3450<путь>`, ответ JSON. Пути извлечены из бинаря
дословно, других в нём нет:

| Путь | Что отдаёт | Зачем в панели |
|---|---|---|
| `/deviceinfo` | серийник, тип, версия, лицензия, имя узла | шапка карточки модема |
| `/status` | живое состояние линка: RSSI, SNR, скорости, узлы, температура | основной экран |
| `/statusadvanced` | детальная статистика по антеннам и подполосам, ошибки CRC, оверфлоу | «подробнее» |
| `/spectrum` | скан спектра / фоновый шум по частотам | выбор чистой частоты (позже) |
| `/config` | полная текущая конфигурация | показать текущие параметры сети |

## Авторизация

Логин у модема **опциональный** — включается флагом:

| Путь | Смысл |
|---|---|
| `GET /isLoginSwitch` | включён ли вход по паролю |
| `GET /loginSwitchSet?loginSwitch=true` \| `false` | включить / выключить вход |
| `/loginPassword?password=<enc>&&newPassword=<enc>` | задать/сменить пароль |

Пароль шифруется на стороне клиента (AES, ключ зашит в конфигураторе:
`mimomeshayakstec`, 16 байт → AES-128; поле `EncryptedPassword`). Для **Этапа 1
это трогать не нужно**: сначала пробуем читать `/status` без авторизации. Если
на нашем стенде `loginSwitch` выключен (а в сохранённых конфигах он не
выставлен) — чтение открыто, и вопрос авторизации не встаёт вовсе. Если
окажется, что включён, — разберём отдельно и не в режиме «только чтение».

## Модель данных (что показывать)

В ответах живёт 239 полей; полный список — в разборе, здесь только то, что
имеет смысл на экране оператора в поле.

**Идентификация:** `deviceSn`, `deviceType`, `meshName`, `id`/`selfId`,
`version`, `ip`, `licenseinfo`, `temp`, `batteryLevel`.

**Качество линка:** `rssi`, `ant1Rssi`, `ant2Rssi`, `noiseRssi`, `nodesRssi`,
`linkQuality`, `linkSnrThreshold`; по подполосам/антеннам —
`subband0Snr{0,1,2}{Avg,Min,Max}` и их усреднённые `aaSubband0Snr…`.

**Соседи и топология:** `nodeInfos`, `nodeNumber`, `nodeStatus`, `addresses`,
`addressTable`, `convergenceLinkNodes`, `heterogeneousLinkNodes`,
`speakingNodes`, `maxHopCount`/`maxHopNum`. Из инструкции: у каждого узла
`ERX` — приём по Ethernet, `PRX` — приём по эфиру, `PTX` — передача в эфир.

**Скорости и загрузка:** `dataRate`, `maxThroughput`, `phyRxBytes`,
`phyTxBytes`, `ethRxBytes`, `ethRxPackets`, `netOverflow`,
`unicastTxOverflow`, `unicastFwOverflow`.

**Ошибки:** `aaCrcErrCount`, `aaCrcErrRatio`, `aaCaptureCount`,
`foAvg/Max/Min` (смещение частоты), `toAvg/Max/Min` (смещение слота).

**Частоты:** `freq`, `operatingFreq`, `freqList`, `freqMode`, `span`,
`operatingCtrlFreqMask`.

## Запись — только Этап 2, и с оговорками

Применение настроек — `POST /config` с JSON-телом. Его схема совпадает с
форматом сохранённых файлов `.msconf`:

```json
{"version": "...", "uniformityParam": {
  "meshName": "NRTK", "freqMode": "adaptiveHopping2", "span": 3,
  "rangeMode": "25", "dataEncryptionMode": 0, "freqList": [...], ...}}
```

Это **«параметры общесетевой согласованности»** (в инструкции помечены `*`):
их значение обязано совпадать на всех узлах, иначе сеть распадётся. Именно
поэтому запись из панели опасна и вынесена в отдельный этап: сменив канал или
мощность на модеме танка, мы теряем с ним связь — и откатить будет нечем,
команда до него уже не дойдёт. Разрешать запись — только после того, как
поймём, умеет ли модем откат по таймеру, и только для модема, который стоит
рядом, а не уехал в поле.
