# Клонирование на несколько устройств

Два способа — в зависимости от того, что удобнее.

## Способ А: побайтовый клон SD-карты (Win32DiskImager и т.п.)

Быстрее всего — переносит всё системное окружение (venv, UART-оверлеи,
sudoers-правила, ZeroTier, MediaMTX). **Но** побайтовая копия дублирует
device-уникальные идентификаторы, которые будут конфликтовать в сети — их
нужно обновить на каждом клоне после первой загрузки.

### Прямо из панели, без SSH

Вкладка «Система» → «Первый запуск (клонированная SD-карта)» → при желании
впиши новое имя устройства → **«Подготовить как новое устройство»**. Одним
нажатием:

- сброс ID узла ZeroTier (иначе клоны «дребезжат» в сети одним ID);
- пересоздание SSH host keys (иначе SSH-клиенты путают устройства);
- пересоздание machine-id;
- смена hostname (если указана);
- перезагрузка.

**Включи пароль на панель** до раздачи клонированных карт — иначе кто угодно
в сети сможет перезагрузить устройство и сбросить его SSH-идентификацию.

### Автоматический экран «новое устройство»

Флаг-файл `data/declone_flag.json` (`{"needs_declone": true}`) перекрывает
всю панель отдельным экраном ещё **до страницы логина** — человеку с
клонированной картой не нужно даже искать кнопку: экран «это новое
устройство» с той же кнопкой первичной настройки показывается сам. После
успешного выполнения флаг сбрасывается автоматически.

`scripts/create_dump.sh` выставляет флаг в архиве автоматически (исходная
машина не затрагивается). При побайтовом клонировании выставь вручную перед
снятием образа:

```bash
echo '{"needs_declone": true}' > ~/groundbridge/data/declone_flag.json
```

### То же самое руками по SSH (если панель недоступна)

```bash
sudo systemctl stop zerotier-one
sudo rm -f /var/lib/zerotier-one/identity.public /var/lib/zerotier-one/identity.secret
sudo rm -rf /var/lib/zerotier-one/networks.d
sudo systemctl start zerotier-one

sudo rm -f /etc/ssh/ssh_host_*
sudo ssh-keygen -A
sudo systemctl restart ssh

sudo rm -f /etc/machine-id
sudo systemd-machine-id-setup

sudo raspi-config nonint do_hostname gb-rover-02   # опционально
sudo reboot
```

## Способ Б: дамп проекта + install.sh на каждом устройстве

Медленнее (пакеты/ZeroTier/MediaMTX ставятся заново), зато без
device-специфичного багажа — каждое устройство генерирует свои
идентификаторы с нуля.

### Шаг 1 — дамп на настроенном устройстве

```bash
cd ~/groundbridge
./scripts/create_dump.sh
```

В архив попадает весь код, твой config.yaml (UART-порты, SBUS, хеш пароля
панели) и сохранённые настройки из data/ (видео/ZeroTier/выходы) с флагом
`needs_declone: true`. **Не попадают**: venv (пересоздаётся install.sh) и
`data/flask_secret.key` (уникален для каждого устройства).

Скрипт печатает подсказку, с какими флагами запускать install.sh на новом
устройстве (вычисляет `--uart`/`--sbus-uart` из твоего config.yaml).
SSID/пароль WiFi-точки задаются вручную — они живут в NetworkManager, не в
проекте.

### Шаг 2 — на новом устройстве

```bash
scp ~/groundbridge-dump-*.tar.gz pi@<новое-устройство>:~/
ssh pi@<новое-устройство>
tar xzf groundbridge-dump-*.tar.gz
cd groundbridge
chmod +x install.sh scripts/*.sh
./install.sh --uart uart4 --sbus-uart uart2   # флаги из подсказки шага 1
```

### Что проверить на каждом устройстве отдельно

- `ls /dev/ttyAMA*` после перезагрузки — существуют ли UART под указанные
  оверлеи (и физически перепроверь пайку).
- USB-устройства могут получить другие `/dev/videoN` / `/dev/input/jsN` —
  путь видео меняется прямо в панели.
- Если у всех машин одна сеть ZeroTier — Network ID/токен приедут в дампе,
  но каждую ноду нужно авторизовать отдельно (или это сделает
  авто-авторизация по токену).
