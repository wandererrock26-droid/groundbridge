# Клонирование на несколько устройств

Два способа — в зависимости от того, что удобнее.

## Способ А: побайтовый клон SD-карты (Win32DiskImager и т.п.)

Быстрее всего — переносит всё системное окружение (venv, UART-оверлеи,
sudoers-правила, ZeroTier, MediaMTX). **Но** побайтовая копия дублирует
device-уникальные идентификаторы, которые будут конфликтовать в сети — их
нужно обновить на каждом клоне после первой загрузки.

### Копия распознаётся сама

Ничего помечать заранее не нужно. При первом запуске станция записывает в
`data/device_identity.json` серийный номер платы, на которой её настроили,
и сверяет его при каждом следующем старте. Серийник зашит в кристалл и с
картой не переезжает — значит, если он не совпал, карта работает не на
своей плате.

Тогда вместо панели открывается экран переустановки: одна кнопка, которая
сбрасывает ID узла ZeroTier, пересоздаёт SSH host keys и machine-id, при
желании меняет hostname и перезагружает устройство. До этого закрыта вся
панель, включая активацию.

Порядок именно такой не случайно. Отпечаток устройства для лицензии
считается в том числе от machine-id, а переустановка его меняет: ключ,
выданный до неё, умрёт через минуту после выдачи. Поэтому сначала
переустановка, потом активация — и никак иначе.

**ZeroTier на нераспознанной копии останавливается сразу**, ещё до того как
человек дойдёт до браузера. Идентификатор узла лежит на карте, у копии он
тот же, что у оригинала, и два узла с одним ID рвут связь друг другу —
причём заметнее это на исходной машине, которая ни в чём не виновата.
Служба снимается с автозапуска (`scripts/clone_hold.sh --hold`) и
возвращается после переустановки.

Физическая перестановка карты в другую плату выглядит для станции точно так
же, как копия, и обрабатывается одинаково. Различить их невозможно, а
делать в обоих случаях надо одно и то же: лицензия всё равно слетит,
идентификаторы всё равно надо пересоздать.

Это **не** защита от копирования. Тот, кто может править файлы на карте,
может стереть и файл свидетеля. От копирования защищает лицензия: отпечаток
считается от того же серийника платы и подписан ключом автора, так что на
чужом железе ключ просто не подойдёт. Задача экрана другая — чтобы человек
увидел «это копия, нажми кнопку», а не молчаливый конфликт двух узлов.

**Смени пароль панели** до раздачи клонированных карт: стандартный
`roverlink` знает кто угодно. Учти, что пароль уедет в клон вместе с дампом
(он лежит в `data/panel_auth.json`) — либо смени его на каждом устройстве
после развёртывания, либо удали этот файл перед снятием дампа, и клоны
поднимутся со стандартным паролем.

### Принудительная пометка

Флаг-файл `data/declone_flag.json` (`{"needs_declone": true}`) включает тот
же экран независимо от железа. Он нужен для случая, когда распознавание по
серийнику не сработает: например, дамп разворачивают на плате, которая
серийный номер не отдаёт.

`scripts/create_dump.sh` выставляет флаг в архиве автоматически (исходная
машина не затрагивается). Вручную:

```bash
echo '{"needs_declone": true}' > ~/roverlink/data/declone_flag.json
```

### То же самое руками по SSH (если панель недоступна)

```bash
sudo systemctl stop zerotier-one
sudo rm -f /var/lib/zerotier-one/identity.public /var/lib/zerotier-one/identity.secret
sudo rm -rf /var/lib/zerotier-one/networks.d
sudo systemctl start zerotier-one

sudo rm -f /etc/ssh/ssh_host_*
sudo ssh-keygen -A
sudo systemctl restart ssh

sudo rm -f /etc/machine-id
sudo systemd-machine-id-setup

sudo raspi-config nonint do_hostname gb-rover-02   # опционально
sudo reboot
```

## Способ Б: дамп проекта + install.sh на каждом устройстве

Медленнее (пакеты/ZeroTier/MediaMTX ставятся заново), зато без
device-специфичного багажа — каждое устройство генерирует свои
идентификаторы с нуля.

### Шаг 1 — дамп на настроенном устройстве

```bash
cd ~/roverlink
./scripts/create_dump.sh
```

В архив попадает весь код, твой config.yaml (UART-порты, SBUS, хеш пароля
панели) и сохранённые настройки из data/ (видео/ZeroTier/выходы) с флагом
`needs_declone: true`. **Не попадают**: venv (пересоздаётся install.sh) и
`data/flask_secret.key` (уникален для каждого устройства).

Скрипт печатает подсказку, с какими флагами запускать install.sh на новом
устройстве (вычисляет `--uart`/`--sbus-uart` из твоего config.yaml).
SSID/пароль WiFi-точки задаются вручную — они живут в NetworkManager, не в
проекте.

### Шаг 2 — на новом устройстве

```bash
scp ~/roverlink-dump-*.tar.gz pi@<новое-устройство>:~/
ssh pi@<новое-устройство>
tar xzf roverlink-dump-*.tar.gz
cd roverlink
chmod +x install.sh scripts/*.sh
./install.sh --uart uart4 --sbus-uart uart2   # флаги из подсказки шага 1
```

### Что проверить на каждом устройстве отдельно

- `ls /dev/ttyAMA*` после перезагрузки — существуют ли UART под указанные
  оверлеи (и физически перепроверь пайку).
- USB-устройства могут получить другие `/dev/videoN` / `/dev/input/jsN` —
  путь видео меняется прямо в панели.
- Если у всех машин одна сеть ZeroTier — Network ID/токен приедут в дампе,
  но каждую ноду нужно авторизовать отдельно (или это сделает
  авто-авторизация по токену).
