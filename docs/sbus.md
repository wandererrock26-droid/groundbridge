# SBUS-выход и режимы CRSF

> **Примечание:** тумблер SBUS временно скрыт из веб-панели (сам выход в
> ядре полностью рабочий и включается через `sbus.enabled`/`sbus.port` в
> config.yaml). Вернуть тумблер: раскомментировать блок `output-sbus-row`
> в `webapp/templates/index.html`.

## SBUS: второй выход для второго полётного контроллера

Если помимо ESP32 (CRSF) на машине стоит второй контроллер с входом
**SBUS RC IN** — мост шлёт оба протокола одновременно, каждый на своём UART,
и любой из них включается/выключается на лету из панели («Выходы
управления»), без перезапуска сервиса. Состояние переключателей хранится в
`data/outputs_state.json`.

### Электрика — важно

SBUS передаётся **инвертированным** UART-сигналом (100000 бод, 8E2). UART
Raspberry Pi сам сигнал не инвертирует. Большинство полётных контроллеров
инвертируют его на своём SBUS-входе сами либо умеют принимать
неинвертированный (настройка/джампер) — уточни для своей платы. Если плата
принимает **только** инвертированный SBUS — между Pi и платой нужен
аппаратный инвертор (NPN-транзистор + два резистора, либо логический
элемент NOT/74HC04).

### Настройка

1. Нужен **отдельный второй UART** (не тот, что занят CRSF):
   ```bash
   ./install.sh --sbus-uart uart3
   # или вручную: dtoverlay=uart3 в /boot/firmware/config.txt + reboot
   ```
2. После перезагрузки найди устройство: `ls /dev/ttyAMA*`.
3. В `config.yaml`:
   ```yaml
   sbus:
     enabled: true
     port: "/dev/ttyAMA3"
     frame_rate_hz: 142
   ```
4. `sudo systemctl restart groundbridge`.

Если `sbus.enabled: false` — переключатель SBUS в панели задизейблен с
пометкой «не настроен».

Диапазон значений каналов SBUS совпадает с CRSF (172/992/1811) — значения из
общего состояния передаются напрямую, без конвертации. Формат кадра:
25 байт (0x0F, 22 байта каналов по 11 бит, флаги, 0x00).

## Режимы CRSF: полётный контроллер / TX-модуль

CRSF используется в двух разных звеньях цепи с разными стандартными
скоростями (по официальной спецификации
[tbs-fpv/tbs-crsf-spec](https://github.com/tbs-fpv/tbs-crsf-spec/blob/main/crsf.md)):

- **приёмник → полётный контроллер**: ~416666 бод (округляют до 420000) —
  режим по умолчанию, подключение к ESP32/FC;
- **радио → TX-модуль** (например, TBS Crossfire/Tracer в module bay):
  **400000 бод** — Pi может заменить собой плату радио и кормить TX-модуль
  напрямую, а тот штатно передаёт управление по воздуху.

Переключение — вкладка «Управление» → «Режим CRSF». Меняется только скорость
UART, на лету (pyserial позволяет менять baudrate открытого порта). Выбор
хранится в `data/outputs_state.json`.

**Скорость — не единственное отличие**: часть TX-модулей ожидает
инвертированный UART-сигнал на входе (историческая совместимость с JR-бэем),
часть — обычный. Если модуль не реагирует — проверь мультиметром уровень
линии в покое на входе модуля: ~3.3V = обычный UART (должно работать сразу),
~0V = нужен аппаратный инвертор (та же схема, что для SBUS выше).
